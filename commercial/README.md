# FR commercial integration candidate

Implementation reference, **not a live commercial service**. Read the [technical manual](../documentation/commercial/03-tecnica.md), [deployment plan](../documentation/commercial/04-comercializacion.md) and [acceptance matrix](../documentation/commercial/07-aceptacion.md) before configuring providers.

- Node 24; built-in SQLite, crypto and HTTP. `node --test tests/commercial.test.mjs`.
- Copy `.env.example` outside the repository, configure real private paths, permitted variants and sandbox credentials. No private key is generated by setup; preserve the existing license authority. Never commit actual secrets.
- Start behind HTTPS: `node --env-file=/private/fr.env commercial/server.mjs`.
- `node --env-file=/private/fr.env commercial/deliver-mail.mjs` defaults to dry run; real delivery requires explicit enabled flag and a verified sender/provider.
- Annual purchases are prepaid one-time payments. Recurring subscription lifecycle is **not implemented**. Do not configure recurring products.
- New offline authorizations expire within 30 days; renew by network or file. Perpetual contractual rights remain distinct. Revocation cannot instantly invalidate a disconnected cached authorization.
- Webhook tests use simulated provider payloads; provider sandbox/live end-to-end, external audit, corporate identity, genuine signing and hosting are pending.
- Signed distribution workflow is `.github/workflows/commercial-signed.yml`; unsigned `desktop.yml` only produces internal QA artifacts.
- Public documentation PDF/DOCX/ZIP is generated from Markdown with `python3 scripts/build-commercial-docs.py` (requires ReportLab and python-docx in the documentation build environment, not on customer computers).

The current source remains a commercial candidate. No Cryptlex/LicenseSpring SDK, payment account, verified publisher certificate or live activation endpoint is claimed.
